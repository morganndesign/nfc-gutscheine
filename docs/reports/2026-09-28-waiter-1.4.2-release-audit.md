## Test device

The device was an Android emulator: Android 9, Google APIs, x86, 1.5 GB RAM, **with a screen-lock PIN set** like every real phone. It ran without hardware virtualisation (CPU emulation). The APK has no 32-bit x86 code, so the app's ARM code also ran through binary translation.

**Backend.** The demo backend ran locally. `app.giftcardpro.at` pointed to it through the emulator's hosts file, with a test CA installed as a system certificate. No production data was touched.

**Limits of this rig.** It runs roughly 50–100× slower than a phone and has **no NFC hardware**. Any result that depends on a timeout or on NFC is therefore not valid here. Such steps are marked **NOT RUN** below rather than reported as pass or fail.

## What is proven

1. The endless launch screen is a 1.4.1 defect (a biometric-mode Keystore key on phones with a screen lock, plus an unguarded `bootstrap`). It is reproduced on a device.
2. 1.4.2 installs over 1.4.1 and leaves the launch screen on the same device. It recovers through "Try again", with the old data reset (the user signs in again).
3. Unit and widget tests: 629/629 green, including the new launch timeout and storage-mode tests.
