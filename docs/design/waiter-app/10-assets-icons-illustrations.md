## 1. Asset principles

1. **Vector first.** Every icon, glyph, illustration and the app mark is mastered as SVG. Raster files exist only where a platform demands them (legacy launcher icons, store listings, screenshots).
2. **One master, generated outputs.** Designers edit only the SVG masters. PDF (iOS), VectorDrawable (Android) and PNG sets are generated by the export pipeline and never edited by hand.
3. **Themed in code, not in files.** Icons and illustrations are exported **monochrome**; colour comes from tokens at runtime (`color.fg.secondary`, `color.accent.saffron`). This keeps one file per asset for light, dark and high-contrast.
4. **Native rendering over animation files.** Motion is rendered natively ([06](06-motion-guidelines.md)). No Lottie or Rive in v1 (decision in §2.6).
5. **Small app.** Asset budget ≤ 2.5 MB of the 25 MB app-size target ([09 §10](09-flutter-handoff.md#10-performance-budgets)).

## 2. Asset list (13)

### 2.1 iOS app icon

**Artwork.** The app mark: a rounded card in ID-1 proportion (1.586 : 1), tilted −8°, in white on `color.brand.ink` #0F172A, with the three saffron NFC arcs (#E8A33D) at the card's top-right corner — the same arcs as on the printed gift card and the `BalanceCard` glyph. No text, no gradients, no transparency.

- Master: `app-mark.svg` on a 1024 × 1024 artboard, square, **no rounded corners** (iOS applies the mask). Keep all content inside the central 824 × 824 area.
- iOS 18 appearance variants (supplied as 1024 masters, single-size asset catalogue):
  - **Default:** ink background, white card, saffron arcs.
  - **Dark:** transparent background (system dark backdrop), white card outline at 90 % opacity, saffron arcs `#F0B454`.
  - **Tinted:** greyscale version (white card, light-grey arcs) on transparent background; iOS tints it.
- Format: PNG, 24-bit sRGB, no alpha for the default variant, no interlacing.

### 2.5 Sounds

Characters, levels and delivery formats are owned by [11 · Sound and haptics](11-sound-and-haptics.md) §6; file names there are binding. Bundled files:

| Token | File (iOS) | File (Android) | Duration | Notes |
|---|---|---|---|---|
| `sound.cardDetected` | `gcw_card_detected.caf` | `gcw_card_detected.ogg` | 60 ms | soft glass tick, 1.6 kHz |
| `sound.success` | `gcw_success.caf` | `gcw_success.ogg` | 280 ms | E6 → B6, the signature sound |
| `sound.warning` | `gcw_warning.caf` | `gcw_warning.ogg` | 150 ms | 660 Hz |
| `sound.error` | `gcw_error.caf` | `gcw_error.ogg` | 2 × 90 ms + 60 ms gap | 330 Hz |

- **Masters:** `gcw_<name>_48k24_master.wav` (WAV 48 kHz / 24-bit mono) plus layered stems, kept in the design source.
- **iOS:** CAF container, linear PCM 16-bit, **48 kHz**, mono (uncompressed for zero decode latency; each file < 30 KB). A reserve AAC-LC `.caf` with trimmed priming is delivered but not bundled ([11 §6.1](11-sound-and-haptics.md)).
- **Android:** Ogg Vorbis q6, **48 kHz**, mono, in `res/raw` (loaded once into a low-latency sound pool at start); a 16-bit WAV variant is delivered for devices with high Ogg decode latency.
- Loudness per token as momentary loudness (LUFS-M) per [11 §2.2](11-sound-and-haptics.md), true peak ≤ −1 dBTP, onset within the first 1 ms (no leading silence), tail fade ≤ 5 ms to digital silence.
- Total sound payload ≤ 150 KB.

### 2.6 Animation files — decision

**Decision: no Lottie, no Rive in v1.** All motion — `NfcScanAnimation` (three concentric saffron arcs + breathing glow), `ProgressRing`, `HoldButton` fill, `CountdownHairline`, `Skeleton` shimmer and `SuccessMark` (circle + check drawn stroke by stroke) — is rendered natively from vector paths with the motion tokens ([06](06-motion-guidelines.md)).

Reasons: pixel-exact token control (durations, springs, Reduce Motion replacements), no runtime dependency (~ 1 MB saved), identical theming in light/dark/high-contrast, and no second source of truth for timing.

**Single fallback (only if the native path-drawing spike fails):** `SuccessMark` may ship as one Lottie file `anim_success_mark.json` (≤ 12 KB, 60 fps, 360 ms, stroke colour bound to a runtime colour property, no embedded images). The fallback requires design sign-off and must honour Reduce Motion (show the final frame with a 160 ms cross-fade). No other animation may use this path.

## 3. Icon list (14)

### 3.1 Rules

1. **Library:** Lucide (ISC licence), pinned version; only the glyphs listed below are imported (no whole icon font). Names follow the current Lucide naming; older aliases are noted for reference.
2. **Grid and stroke:** 24 × 24 grid, 2 pt padding, round caps and joins, no fills. Stroke per size token ([04 §11.2](04-design-system.md)): `icon.16` 1.5 · `icon.20` 1.75 · `icon.24` 1.75 · `icon.32` 2.0 · `icon.48` 2.5 pt. **Strokes never scale with the icon** — each size uses its own stroke, so exports are per size, not scaled.
3. **Colour:** `color.fg.primary` for actions, `color.fg.secondary` for decorative/leading icons, status colours only inside status components. Never saffron except the NFC glyph and focus/hold accents.
4. **One icon per meaning, everywhere** (semantic map: [04 §11.4](04-design-system.md)). If a meaning is not in the list, it gets no icon.
5. **Never alone** except Close, Recent, Menu, ⌫, torch, password visibility — all with labels from [12](12-ui-copy-and-error-messages.md).
6. **Direction:** no icon is mirrored for RTL (no RTL locales in v1).
7. **Formats:** SVG master → iOS PDF (single scale, "Preserve Vector Data", rendered as template image) · Android VectorDrawable XML (`android:tint` from theme). One file per icon and size token where the stroke differs.

## 4. Illustration style (15)

### 4.1 Purpose

Illustrations help the waiter recognise a situation **at a glance, before reading**. They appear only where the screen has no card to show:

- **Problem screens** (S10) and session/account states (S15) — the most frequent problems get an illustration; rare ones use a 48 pt icon.
- **Empty state** — Recent (S13) with no redemptions yet.
- **First-run intro** (S17) — three cards.

Never on S05, S07, S08, S09 (the card, the amount and the `SuccessMark` are the heroes), never in banners, never as decoration.

### 4.2 Style

| Property | Rule |
|---|---|
| Line | **Monoline 1.75 pt** at the delivered size (120 pt, 96 pt, 160 pt); strokes do not scale — each size is drawn/exported with its own 1.75 pt stroke. Round caps, round joins. |
| Colour | Lines in **`color.fg.secondary`**. **Exactly one saffron accent** (`color.accent.saffron`) per illustration — the element that carries the meaning (the question mark, the arcs, the hourglass sand). No other colours, no status colours. |
| Fill | None, except an optional knock-out in `color.bg.canvas` where lines must visually cross in front of each other. |
| Geometry | Geometric primitives: rectangles with 2 pt radius, circles, straight lines, 45°/90° angles. Objects shown frontal or in simple 2D; the card is always the ID-1 rounded rectangle from the app mark. |
| People | **No people, no faces, no hands.** (The tap is shown by the arcs, not by a hand.) |
| Not allowed | 3D, perspective, isometric, gradients, shadows, textures, photos, emoji, text or numbers inside the artwork (text would need localisation). |
| Composition | One subject, centred on the artboard, 8 % padding inside the artboard; optical centre 4 % above geometric centre. |
| Accessibility | Decorative — hidden from VoiceOver/TalkBack; the title and body carry the meaning ([12 §1.10](12-ui-copy-and-error-messages.md#110-accessibility-strings)). |

> **Relation to [04 §12](04-design-system.md).** This document is the authoritative owner of illustration style, sizes and inventory; 04 §12, [03b §5.1](03b-screens-charge-redeem-success-problems.md) and [05 §4.6](05-component-library.md) only summarise and link here. Lines use `fg.secondary` (one step below the title in hierarchy); the Recent empty state is 96 pt (it sits inside a sheet).

### 4.3 Sizes

| Context | Artboard | Placement |
|---|---|---|
| Problem and account screens (S10, S15) | **120 × 120 pt** | Centred above the title, `space.8` (32) gap to the title |

| Text size ≥ 150 % | Problem screens hide the illustration | Space is given to the text ([07](07-accessibility-guidelines.md)) |

### 4.5 Dark mode and high contrast

- Illustrations are single SVGs with two named colour roles (`line`, `accent`); the renderer maps them to `color.fg.secondary` and `color.accent.saffron` of the active theme. Light: `#52525B` / `#E8A33D`; dark: `#A1A1AA` / `#F0B454`.
- Knock-outs use `color.bg.canvas` of the active theme (or `color.bg.surface` inside sheets).
- **High contrast** (Increase Contrast / High contrast text): lines switch to `color.fg.primary`, stroke +0.25 pt; saffron unchanged.
- No separate dark files, no inverted rasters.

### 4.6 Export

| Target | Format | Notes |
|---|---|---|
| Design master | SVG 1.1, artboard = delivered size, strokes as strokes (not outlined), colour roles as named groups `line` / `accent` / `knockout` | One file per illustration and size where the size differs (120, 96, 160, plus compact 96/120 variants re-drawn with 1.75 pt) |
| App | Same SVG, rendered as vector at runtime with theme colours | No PNGs in the app |
| Store / marketing | PNG @3x exported from the master when needed | Not shipped in the app |

Illustration SVG budget: ≤ 6 KB per file, ≤ 80 KB total.
